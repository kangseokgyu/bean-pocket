## 접근 확인

Notion 커넥터의 도구 접근 확인에서 스키마 생성·수정·조회 도구를 사용할 수 있었다. 운영 스키마는 읽기 전용으로 수집했고, 개인 식별자가 있는 원문은 `.state/T05-operating-schema.json`에만 보관했다. `.state/`가 Git에서 제외되는지 `git check-ignore`로 확인했다(종료 0).

기존 `.env.local`의 앱용 토큰을 복사·출력하지 않고 새 테스트 데이터 소스 5개에 `GET /v1/data_sources/{id}`만 수행했다. 버전은 기존 서버와 같은 `2025-09-03`이다. Node 명령 종료는 0이며 이는 확인 절차가 실행됐다는 의미다. API 접근은 아래와 같이 모두 실패했다.

| 데이터 소스 | HTTP | Notion code |
|---|---|---|
| 원두 | 404 | object_not_found |
| 원두 봉지 | 404 | object_not_found |
| 레시피 | 404 | object_not_found |
| 물 붓기 단계 | 404 | object_not_found |
| 추출 기록 | 404 | object_not_found |

공유 전에는 커넥터가 생성한 테스트 공간에 앱용 내부 연결이 접근하지 못하는 상태로 분류했다. 사용자에게 테스트 부모 페이지에서 기존 내부 연결을 추가하도록 안내했고, 이후 아래와 같이 재확인했다. 토큰 변경이나 브라우저 보안 우회는 수행하지 않았다.

### 사용자 연결 추가 이후 재검증

사용자가 “기존 앱용 연결을 추가했어요”라고 응답했다. 같은 로컬 토큰·API 버전으로 테스트 데이터 소스 5개에 GET을 한 번씩 다시 수행했다. Node 명령 종료 0, **5개 모두 HTTP 200**이다.

API 응답 원문을 기존 코드 및 테스트 설정과 비교하는 Node assertion 검사도 종료 **0**이다.

- 데이터 소스 5개의 식별자가 저장된 테스트 설정과 일치.
- 기존 쓰기 속성 33개 이름·타입 모두 일치.
- 양방향 관계 10방향(5쌍)이 모두 대응하는 테스트 DB를 가리키며 역방향 속성명도 일치.
- 평가 횟수 수식 원문이 정확히 `prop("추출 기록").length()`.
- 평균 별점 rollup이 `추출 기록` 관계 → `별점` 속성 → `average`.

신규 레코드 생성이나 수정·보관 요청은 하지 않았다. 사용자가 연결의 콘텐츠 읽기·삽입·수정 기능이 모두 허용되어 있음을 명시적으로 확인했다. 실제 생성·부분 저장 복구 동작 및 iPhone 교차 출처 통신은 T06 실험에서 직접 확인한다.

[Notion 공식 연결 권한 안내](https://developers.notion.com/guides/get-started/internal-connections#granting-page-access)를 2026-10-18에 확인했다. 내부 연결은 사용자 커넥터와 별도 접근 주체이며 부모 페이지의 접근이 자식에 상속된다.

## 비공개 증거

- `.state/T05-operating-schema.json`: 운영 부모·스키마 원문
- `.state/T05-test-config.json`: 테스트 부모·DB·데이터 소스 식별자 (토큰 없음)
- `.state/T05-test-evidence.json`: 생성·설정·조회 결과
- `.state/T05-integration-read.json`: 앱용 토큰의 GET 결과 원문 (토큰 없음)
- `.state/T05-integration-read-after-sharing.json`: 사용자 연결 추가 후 5개 GET 200 응답 원문 (토큰 없음)
- `.state/T05-api-schema-check.json`: 공유 후 속성·관계·수식·집계 assertion 검사 요약

위 파일은 Git 제외 대상이며 공개 저장소·산출물에 포함하지 않는다. 원격 페이지 주소·실제 식별자는 이 공개 증거에 기록하지 않는다.

앱용 연결의 읽기·삽입·내부 복구 권한을 확인하기 전 T05 완료로 판정하지 않는다. 커넥터 성공이나 Node GET 결과를 실제 iPhone의 교차 출처 통신 성공으로 해석하지 않는다. 임의 레코드 생성·보관 취소 실험은 이 준비 단계에서 수행하지 않는다.
