## 생성·스키마 확인 결과

별도 비공개 부모 아래 테스트 DB 5개를 생성했다. 테스트 스키마 준비는 완료했고 앱 API 권한 등 아래 미검증 항목이 있어 **T05 전체는 검증 대기**다.

| 확인 | 실제 결과 |
|---|---|
| 테스트 데이터 소스 수 | 서로 다른 5개 |
| 운영과 ID 분리 | 신규 부모·DB·데이터 소스 ID 11개가 운영 보관본의 모든 UUID와 겹치지 않음 |
| 쓰기 속성 | 기존 코드의 33개 속성 이름·타입과 호환 |
| 관계 | 양방향 5쌍, 모두 테스트 DB 내부 대상 |
| 스냅샷 | 추출 기록의 `당시 레시피 스냅샷`은 rich_text |
| 평균 별점 | 추출 기록 관계·숫자 별점·average 집계를 재조회 |
| 평가 횟수 | `prop("추출 기록").length()` 적용 DDL 성공, formula 타입 재조회. 수식 원문은 connector의 코드 URL 조회 제한으로 독립 확인하지 못함 |
| 빈 목록 | 테스트 5개 각각 `results: []`, `has_more: false` |
| 운영 쓰기·테스트 레코드 생성 | 작업 호출 0건. 운영 불변 판단은 호출 대상 격리와 ID 분리에 근거하며 운영 전후 전체 재조회 비교는 하지 않음 |

Notion 생성·스키마 수정·재조회·빈 목록 조회 도구가 성공했고 worker의 로컬 ID 분리·파일 보관 검증은 종료 0이다. 실제 집계 수치 검증이나 레코드 생성·복구 동작 검증은 수행하지 않았다.

## 접근 확인

Notion 커넥터의 도구 접근 확인에서 스키마 생성·수정·조회 도구를 사용할 수 있었다. 운영 스키마는 읽기 전용으로 수집했고, 개인 식별자가 있는 원문은 `.state/T05-operating-schema.json`에만 보관했다. `.state/`가 Git에서 제외되는지 `git check-ignore`로 확인했다(종료 0).

기존 `.env.local`의 앱용 토큰을 복사·출력하지 않고 새 테스트 데이터 소스 5개에 `GET /v1/data_sources/{id}`만 수행했다. 버전은 기존 서버와 같은 `2025-09-03`이다. Node 명령 종료는 0이며 이는 확인 절차가 실행됐다는 의미다. API 접근은 아래와 같이 모두 실패했다.

| 데이터 소스 | HTTP | Notion code |
|---|---|---|
| 원두 | 404 | object_not_found |
| 원두 봉지 | 404 | object_not_found |
| 레시피 | 404 | object_not_found |
| 물 붓기 단계 | 404 | object_not_found |
| 추출 기록 | 404 | object_not_found |

커넥터가 생성한 테스트 공간에 앱용 내부 연결이 접근하지 못하는 상태로 분류한다. 404만으로 모든 원인을 확정하지 않으며, 사용자에게 테스트 부모 페이지에서 기존 내부 연결을 추가하도록 안내했다. 완료 응답 후 한 번 재조회해 판정을 갱신한다. 토큰 변경이나 브라우저 보안 우회는 수행하지 않았다.

[Notion 공식 연결 권한 안내](https://developers.notion.com/guides/get-started/internal-connections#granting-page-access)를 2026-10-18에 확인했다. 내부 연결은 사용자 커넥터와 별도 접근 주체이며 부모 페이지의 접근이 자식에 상속된다.

## 비공개 증거

- `.state/T05-operating-schema.json`: 운영 부모·스키마 원문
- `.state/T05-test-config.json`: 테스트 부모·DB·데이터 소스 식별자 (토큰 없음)
- `.state/T05-test-evidence.json`: 생성·설정·조회 결과
- `.state/T05-integration-read.json`: 앱용 토큰의 GET 결과 원문 (토큰 없음)

위 파일은 Git 제외 대상이며 공개 저장소·산출물에 포함하지 않는다. 원격 페이지 주소·실제 식별자는 이 공개 증거에 기록하지 않는다.

앱용 연결의 읽기·삽입·내부 복구 권한을 확인하기 전 T05 완료로 판정하지 않는다. 커넥터 성공이나 Node GET 결과를 실제 iPhone의 교차 출처 통신 성공으로 해석하지 않는다. 임의 레코드 생성·보관 취소 실험은 이 준비 단계에서 수행하지 않는다.

## 역할과 남은 검증

기존 에이전트를 같은 모델·추론 설정으로 재사용했다: orchestrator Socrates (`gpt-6.1-sol`, medium) → worker Helmholtz (`gpt-6-luna`, max) → critic Nietzsche (`gpt-6.1-sol`, medium). orchestrator가 T05 범위·완료 조건을 정했고 worker가 생성·확인을 수행했다.

critic 독립 검토는 **PASS**다. 비공개 생성·조회 원문과 운영 보관 스키마, 기존 코드를 직접 대조해 속성 33개·분리된 객체 11개·관계 10방향/5쌍·빈 조회 5건을 확인했다. 공개 증거가 남은 권한·수식 원문·집계값 검증을 완료로 과장하지 않았음을 확인했다. 로컬 대조 검사는 종료 0, 비공개 파일 4개 모두 Git 제외 확인. 추가 원격 조회나 쓰기는 하지 않았다. 스키마 준비의 검토 통과가 T05 전체 완료를 의미하지 않는다.

남은 항목: 테스트 부모의 앱용 연결 추가, 앱 API 읽기 재확인과 formula 원문 확인, 읽기·삽입·내부 복구 권한 확인 수준 정리. T04 실제 기종·iOS 등 추가 결과와 T06/T08 실기기 게이트도 유지한다.
