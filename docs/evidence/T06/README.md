# T06 Notion 직접 통신 — 실험판 준비 및 PC 일부 검증

2026-10-18 (Asia/Seoul). 사용자 명시적 승인 후 실험판을 main에 통합하고 Pages에 게시했다. [게시 기록](pages-deploy.md). iPhone 12 / iOS 27.0.1의 Safari·홈 화면 통신 검증은 대기다.

## 구현과 실행 절차

일반 `npm run build:pages`에는 실험 페이지가 없다. 명시적 `npm run build:probes`와 `npm run check:probes`로만 포함하며 홈 화면에 실험 메뉴가 생긴다. 빌드에 실제 토큰이나 데이터 소스 ID를 넣지 않는다.

1. 별도 테스트 원두 대상의 토큰·데이터 소스 UUID를 화면에서 입력한다. 입력은 메모리에만 둔다.
2. `원두 스키마 조회`로 원두 제목·속성 타입·대상 ID를 확인한다. 조회 성공만으로 테스트 DB 여부나 생성 권한을 보장하지 않는다.
3. Notion에서 운영과 분리된 테스트 대상임을 확인한 후 체크하고 `테스트 원두 1개 생성`을 한 번 누른다. 생성과 생성 항목 재조회를 구분해 표시하며 자동 정리·삭제 요청은 없다.
4. 응답 유실·시간 초과·5xx·잘못된 응답이면 재전송하지 않는다. 같은 설정을 유지하고 Notion 원본 확인 체크 후 정상 스키마 재조회를 완료한다. 잠금은 메모리 상태이므로 종료·새로고침 전에 원본을 확인하고 결과를 기록한다. 전체 앱의 영속 복구·다른 창 중복 제어는 아직 구현하지 않았다.
5. `잘못된 인증으로 401 확인`은 별도 가짜 인증값으로 실행한다. 실제 인증·권한 실패도 각각 기록한다. 네트워크 응답 미확인만으로 CORS 차단이라고 단정하지 않는다.

## 검증 결과

- 모의 요청 테스트: 중복 클릭, 설정·payload 고정, 불확실 생성 잠금, 성공 후 재조회 실패, 입력 비밀값·원문 응답 비노출을 검증했다. 전체 통합 결과는 T11 기록에 남긴다.
- 로컬 PC 인앱 브라우저의 `http://localhost:4189/bean-pocket/probes/notion/`: 가짜 인증값의 실제 직접 요청에서 **HTTP 401을 읽고 표시**했다. 프록시·브라우저 보안 변경은 사용하지 않았다. [화면](local-notion-401.png).
- 실제 토큰을 브라우저에 입력하지 않았고 실제 레코드 생성도 하지 않았다. 정상 조회·생성·권한 오류·실제 Pages 출처·iPhone 두 모드는 미검증이다. 이 결과로 T06 통과 또는 T09 착수 가능을 판정하지 않는다.
