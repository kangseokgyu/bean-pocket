# T06 Notion 직접 통신 — PC・iPhone 일부 검증

2026-10-18 (Asia/Seoul). 사용자 명시적 승인 후 실험판을 main에 통합하고 Pages에 게시했다. [게시 기록](pages-deploy.md). iPhone 12 / iOS 27.0.1의 Safari·홈 화면에서 잘못된 인증 HTTP 401 확인을 사용자에게 보고받았다. 이후 두 모드의 정상 인증 스키마 조회도 사용자에게 보고받았다. 이후 두 모드의 명시적 생성·생성 항목 재조회 성공도 보고받았다. 이후 두 모드의 존재하지 않는 시험 대상 HTTP 404 식별도 보고받았다. 이후 PC의 정상 인증 스키마 조회 성공도 사용자에게 보고받았다. 최종 증거 검토는 대기다.

## 구현과 실행 절차

일반 `npm run build:pages`에는 실험 페이지가 없다. 명시적 `npm run build:probes`와 `npm run check:probes`로만 포함하며 홈 화면에 실험 메뉴가 생긴다. 빌드에 실제 토큰이나 데이터 소스 ID를 넣지 않는다.

1. 별도 테스트 원두 대상의 토큰·데이터 소스 UUID를 화면에서 입력한다. 입력은 메모리에만 둔다.
2. `원두 스키마 조회`로 원두 제목·속성 타입·대상 ID를 확인한다. 조회 성공만으로 테스트 DB 여부나 생성 권한을 보장하지 않는다.
3. Notion에서 운영과 분리된 테스트 대상임을 확인한 후 체크하고 `테스트 원두 1개 생성`을 한 번 누른다. 생성과 생성 항목 재조회를 구분해 표시하며 자동 정리·삭제 요청은 없다.
4. 응답 유실·시간 초과·5xx·잘못된 응답이면 재전송하지 않는다. 같은 설정을 유지하고 Notion 원본 확인 체크 후 정상 스키마 재조회를 완료한다. 잠금은 메모리 상태이므로 종료·새로고침 전에 원본을 확인하고 결과를 기록한다. 전체 앱의 영속 복구·다른 창 중복 제어는 아직 구현하지 않았다.
5. `잘못된 인증으로 401 확인`은 별도 가짜 인증값으로 실행한다. 실제 인증·권한 실패도 각각 기록한다. 네트워크 응답 미확인만으로 CORS 차단이라고 단정하지 않는다.

## 검증 결과

- 모의 요청 테스트: 중복 클릭, 설정·payload 고정, 불확실 생성 잠금, 성공 후 재조회 실패, 입력 비밀값·원문 응답 비노출을 검증했다. 전체 통합 결과는 T11 기록에 남긴다.
- 로컬 PC 인앱 브라우저의 `http://localhost:4189/bean-pocket/probes/notion/`: 가짜 인증값의 실제 직접 요청에서 **HTTP 401을 읽고 표시**했다. 프록시·브라우저 보안 변경은 사용하지 않았다. [화면](local-notion-401.png).
- 에이전트는 실제 토큰을 브라우저에 입력하거나 레코드를 생성하지 않았다. 사용자는 아래 기록처럼 iPhone 두 모드에서 정상 인증 스키마 조회 성공을 보고했다. 이후 사용자는 두 모드 각각 명시적 생성·생성 항목 재조회 성공도 보고했다. 접근 불가/존재하지 않는 시험 대상 HTTP 404는 후속 사용자 보고로 확인했다. PC 정상 인증 스키마 조회도 후속 사용자 보고로 확인했다. 실제 Pages 출처의 가짜 인증 HTTP 401은 PC에서 직접 확인했고, iPhone 두 모드에서는 아래 사용자 보고를 받았다. 이 결과로 T06 통과 또는 T09 착수 가능을 판정하지 않는다.


## iPhone 사용자 보고 — 2026-10-18 수신

- 환경: 사용자 확인 iPhone 12 / iOS 27.0.1.
- 사용자 원문: `Safari: 7a9015e1e222, HTTP 401 / 홈 화면: 동일`.

| 실행 모드 | 표시 빌드 | 잘못된 인증 응답 |
|---|---|---|
| Safari | `7a9015e1e222` | HTTP 401 사용자 확인 |
| 홈 화면 | `7a9015e1e222` | HTTP 401 사용자 확인 |

사용자가 수행한 실기기 결과이며 에이전트의 직접 관찰이나 화면 증거 확보를 의미하지 않는다. 개별 실행 시각은 받지 않았다. 정상 토큰의 스키마 조회는 후속 사용자 보고로 확인했다. 명시적 테스트 생성·생성 항목 재조회는 후속 보고로 확인했으며 존재하지 않는 시험 대상 HTTP 404도 후속 보고로 확인했다. T06 전체 통과 및 T09 통과 판정은 보류한다.


## iPhone 정상 인증 스키마 조회 — 사용자 보고

2026-10-18 수신. 별도 테스트 원두 데이터 소스 ID를 비공개 설정에서 확인해 사용자에게 전달하고, Safari와 홈 화면 각각에서 앱용 토큰·해당 ID로 “원두 스키마 조회”만 실행하도록 안내했다. 사용자는 두 모드 모두 다음 문구가 나왔다고 보고했다.

> 원두 스키마를 정상 조회했습니다. 이 결과만으로 테스트 DB 여부나 생성 권한을 보장하지는 않습니다.

두 모드 모두 정상 인증의 직접 스키마 조회 성공을 사용자 보고로 기록한다. 사용자 보고된 스키마 성공 문구는 생성 권한 확인이나 레코드 생성·재조회 성공을 의미하지 않는다. 실제 토큰·대상 ID·원문 API 응답은 공개 증거에 포함하지 않는다. 이번 조회의 화면 빌드·실행 시각·화면 증거는 별도로 받지 않았다.


## iPhone 명시적 생성·생성 항목 재조회 — 사용자 보고

2026-10-18 수신. Safari와 홈 화면 각각 별도 테스트 원두 대상 확인 체크 후 “테스트 원두 1개 생성”을 한 번씩 실행하도록 안내했다(모드별 한 건, 합계 두 건을 의도한 실험). 사용자는 두 모드 모두 다음 문구가 나왔다고 보고했다.

> 생성 성공과 생성 항목 재조회를 확인했습니다. 새 생성을 하려면 원본 확인 체크 후 다시 조회해 주세요.

각 모드의 직접 생성 요청과 생성 항목 GET 재조회 성공을 사용자 보고로 기록한다. 에이전트가 직접 생성하거나 실제 레코드 수를 별도 API 조회로 세지는 않았다. 자동 정리·삭제는 하지 않았다. 이번 실행의 화면 빌드·시각·화면 증거·실제 항목 ID는 별도 수신하지 않았다.

두 모드 모두 정상 인증 스키마 조회·명시적 생성·재조회와 잘못된 인증 HTTP 401 응답을 사용자 보고로 확보했다. 존재하지 않는 시험 대상 HTTP 404 응답 식별도 후속 보고로 확인했다. PC 정상 인증 스키마 조회도 후속 보고로 확인했다. T08 최종 증거 판정과 함께 T09에서 검토하며 아직 전체 이전 통과로 선언하지 않는다.


## iPhone 없는 시험 대상 HTTP 404 — 사용자 보고

2026-10-18 수신. 생성 이후 Notion 원본 확인 체크·정상 스키마 조회로 잠금을 해제한 뒤, 실제 테스트 ID 대신 존재하지 않는 형식상의 UUID 시험값으로 “원두 스키마 조회”만 실행하도록 안내했다. 사용자는 아래 결과를 보고하고, 추가 확인에서 Safari·홈 화면 모두 같은 결과였다고 명시했다.

> 조회가 거부됐습니다. 인증과 연결 권한을 확인해 주세요. (HTTP 404)

두 모드 모두 존재하지 않거나 접근 불가한 대상의 HTTP 404를 브라우저에서 읽고 표시하는 동작을 사용자 보고로 확인했다. 이 결과는 실제 비공유 DB의 403 권한 거부나 다른 모든 오류 분류를 확인한 것은 아니다. 이 시험에서는 생성 버튼을 누르도록 안내하지 않았으며 추가 생성·삭제를 에이전트가 수행하지 않았다.

iPhone Safari·홈 화면의 정상 인증 스키마 조회·명시적 생성·생성 항목 재조회·잘못된 인증 401·없는 대상 404 결과를 모두 확보했다. 화면 증거·개별 실행 시각·일부 화면 버전값은 별도 확보하지 않았다. PC 정상 인증 스키마 조회는 후속 사용자 보고로 확인했으며 T08 증거와의 최종 판정은 남아 있다.


## PC 정상 인증 스키마 조회 — 사용자 보고

2026-10-18 수신. PC의 실제 Pages Notion 실험 화면에서 같은 앱용 토큰·별도 테스트 데이터 소스 ID로 “원두 스키마 조회”만 실행하도록 안내했고, 사용자가 다음 결과를 보고했다.

> 원두 스키마를 정상 조회했습니다. 이 결과만으로 테스트 DB 여부나 생성 권한을 보장하지는 않습니다.

PC 정상 인증 직접 스키마 조회 성공을 사용자 보고로 기록한다. 에이전트가 토큰을 PC 브라우저에 입력하거나 직접 관찰한 결과는 아니다. PC 브라우저 종류·OS·화면 빌드·개별 실행 시각·화면 증거는 별도 수신하지 않았다. PC의 생성·재조회 성공으로 확대하지 않는다. iPhone 두 모드의 조회·생성·재조회·401·404는 앞선 사용자 보고로 별도 확인했다.
