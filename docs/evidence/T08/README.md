# T08 저장 수명 실험 — 동작 관찰 확인, 증거 판정 대기

2026-10-18 (Asia/Seoul). iPhone 12 / 사용자 확인 iOS 27.0.1. 기존 절차와 수신된 사용자 보고를 함께 보관한다. 두 모드의 종료·재실행 및 A/B 업데이트 후 동일 지문, “북마크 삭제” 후 홈 화면 재설치 시 파일 없음·Safari 기존 지문 유지는 사용자 보고로 확인했다. **동작 관찰 확인 / 증거 판정 대기**이며 T08 전체 통과 판정은 아니다. 개별 실행 시각은 미수신이다.

## 시험판과 게시 순서

- A(업데이트 전 기준): 커밋 `7aa0c54`, 빌드 `7a9015e1e222`.
- B: 실험 페이지의 홈 이동 링크와 Notion 화면 이탈 안내를 추가한 빌드 `0f0ea09f28a8`. OPFS 경로·파일명·버전 JSON·읽기/쓰기 모듈과 manifest scope는 A와 동일하다. A 기준 지문 확보 후 사용자 승인으로 main 통합·게시했다([게시 기록](pages-b-deploy.md)).
- 출처: `https://kangseokgyu.github.io`, 경로·scope: `/bean-pocket/`.
- 당시 게시 순서: 먼저 A에서 아래 1~3단계의 파일 지문·기기·모드 기록을 확보한 뒤 B 변경·검증 결과에 대한 사용자 merge 승인을 받고 기존 T02 경로에서 `probes=true`로 게시하도록 정했다. 이후 모드별 A 기준 지문 확보와 승인된 B 게시를 완료했다. 원래 절차는 아래에 보존하며 반복 수행을 요구하지 않는다.

## 당시 안내한 실행 순서 — 원문 절차 보존

아래는 기존 안내 절차다. 실제 보고된 삭제 조작은 6단계의 “완전 삭제”라는 안내 문구와 구분해 **북마크 삭제 → 홈 화면 재설치**로 기록한다. 최신 관찰과 판정은 결과표와 현재 판정을 따른다. 모든 동작을 다시 실행하라는 지시가 아니다.

1. Safari와 홈 화면을 각각 열어 A 빌드를 기록한다. 두 모드의 파일 공유 여부는 가정하지 않는다. 이미 시험 파일이 있다면 먼저 읽기 결과를 기록하고 새 시험 시작 여부를 결정한다.
2. 새 시험을 시작하는 모드에서 가짜 문자열을 작성하고 SHA-256 지문을 별도로 기록한다. 다른 모드의 작성이 앞선 파일을 바꿨다면 공유 관찰을 기록하고, 마지막 쓰기 뒤 두 모드 모두 다시 읽어 각 모드의 업데이트 직전 기준 지문을 확정한다.
3. Safari의 해당 사이트 탭과 홈 화면 앱을 종료하고 다시 열어 **읽기만** 실행한다. 새 작성 없이 기준 지문과 비교한다. 시각·모드·빌드·화면 증거를 기록한다.
4. B 게시 후 동일 주소에서 실행한다. 홈과 실험 화면 모두 B 빌드인지 확인한다. 실험 페이지는 SW 캐시에 없으므로 실험 화면만 B이고 홈은 A일 수 있다. 그런 경우 진행 중 요청이 없는 상태에서 해당 사이트 탭과 앱을 종료·재실행한다. 두 화면이 B임을 확인하기 전에는 업데이트 검증 완료로 세지 않는다.
5. B에서 **읽기만** 실행해 모드별 기준 지문이 유지되는지 확인한다. 파일 없음·지문 변화·손상·권한 오류는 그대로 기록하고 재작성해 성공으로 바꾸지 않는다.
6. 업데이트 결과를 확보한 다음, 홈 화면 설치를 완전히 삭제한다. 실제 선택한 OS 메뉴·시각과 삭제 전 지문을 기록한다. Safari 사이트 데이터 수동 제거, OPFS 수동 삭제, 토큰 폐기는 하지 않는다.
7. 같은 HTTPS 주소를 홈 화면에 다시 추가하고 **새 파일을 쓰기 전에 읽기만** 실행한다. 파일 없음인지, 기존 지문인지 기록한다. Safari의 파일 결과도 별도로 관찰하되 삭제·초기화하지 않는다.
8. Notion 원본과 다른 기기에는 삭제·변경 작업을 하지 않았음을 기록한다. 파일이 남았다면 삭제 수명 요구 통과로 판정하지 않고 T09에서 원인·대안 결정을 다룬다.

토큰·실제 연결 설정은 이 실험에 사용하지 않는다. 홈 화면 삭제는 사용자가 실기기에서 수행하며, 이 문서는 삭제를 실행했다는 증거가 아니다.

## 현재 판정

**최신 판정: 동작 관찰 확인 / 증거 판정 대기.** 두 모드의 종료·재실행 및 A/B 업데이트 후 기준 지문 유지를 사용자 보고로 확인했다. 실제 삭제 메뉴는 후속 원문에 따라 “북마크 삭제”로 기록하고, 홈 화면 재설치 후 파일 없음·Safari 기존 지문 유지라는 관찰을 보존한다.

PLAN의 실기기 화면 증거, “북마크 삭제”와 완전 삭제 조건의 대응, Notion 원본·다른 기기 영향 확인 기록은 아직 미수신·미확정이다. 개별 실행 시각도 미수신으로 유지한다. [공식 근거 검토](../T09/source-review.md)는 플랫폼 정책과 설치·삭제 조작의 의미를 해석하는 참고자료이며 실제 사용자 조작 증거를 대신하지 않는다. 공식 웹문서만으로 실제 “북마크 삭제”를 PLAN의 완전 삭제와 동일하다고 확정하지 않는다.

T06는 iPhone 두 모드의 조회·생성·재조회·401·404 및 PC 정상 인증 스키마 조회·401 동작 확인을 반영한 **증거 보완 상태**다([T06 기록](../T06/README.md)). PC 정상 조회나 T06 정상 인증 동작 전체를 대기로 돌리지 않는다. 남은 범위는 증거 보완과 판정이며 모든 동작 반복·PC 추가 POST·403 별도 시험을 새 요구로 추가하지 않는다. **T09 보류 / T10 최종 확정 및 T12 이후 전체 이전 차단**을 유지한다([현재 기술 게이트](../../technical-gates.md)).

## 삭제 조작 후속 설명

2026-10-18 수신. 사용자 원문: “사파리는 새로고침해서 빌드번호 확인 후 파일 확인. 홈화면은 북마크 삭제 후 다시 홈화면에 설치하고 파일확인 진행햇어”.

실제 보고된 조작명은 **북마크 삭제**다. Safari에서는 새로고침 후 빌드 번호를 확인하고 파일을 읽었다. 사용자가 설명한 조작에 Safari 사이트 데이터 수동 제거는 포함되지 않았으며, 별도의 제거 작업이 있었다고 기록하지 않는다. 기존에 안내한 “앱 완전 삭제”를 그대로 수행했다고 가정하지 않고 후속 설명을 우선한다.

관찰 결과(홈 화면 재설치 후 파일 없음·Safari 기준 지문 유지)는 유지한다. “북마크 삭제”라는 OS 조작이 PLAN의 완전 삭제 조건과 정확히 대응하는지는 화면·추가 근거 없이 확정하지 않는다. 이 단일 관찰을 근거로 모든 설치·삭제 경로의 파일 수명을 보장하지 않는다. T08 최종 판정은 증거 범위와 이 제한을 함께 검토해야 한다.
