# T09 외부 근거 검토 — 실기기 증거와 구분

2026-10-18 (Asia/Seoul). 공식 Apple/WebKit 자료를 확인했다. 이 문서는 사용자 기기에서 실제로 어떤 조작을 했는지의 증거를 대신하지 않는다.

- [Apple: iPhone에서 웹사이트를 앱으로 만들기](https://support.apple.com/ko-kr/guide/iphone/iphea86e5236/27/ios/27): 홈 화면 추가 시 ‘웹 앱으로 열기’를 켜는 절차를 안내한다. 사용자 기기의 실제 선택 여부는 이 문서만으로 확인할 수 없다.
- [WebKit: Safari 26.0의 홈 화면 웹 앱](https://webkit.org/blog/17333/webkit-features-in-safari-26-0/): 홈 화면 추가 시 기본 웹 앱 실행과 ‘Open as Web App’을 끄는 브라우저 북마크 방식을 구분한다. 따라서 삭제 메뉴의 ‘북마크’라는 단어만으로 실제 실행 모드나 저장 컨테이너를 단정하지 않는다. 실험 화면의 실행 모드 기록과 실제 OS 조작을 함께 확인해야 한다.
- [WebKit: Safari 17.2의 웹 앱 저장소](https://webkit.org/blog/14787/webkit-features-in-safari-17-2/): 웹 앱 추가 시 쿠키 복사와 그 외 로컬 데이터의 비공유를 설명한다. Safari 지문 유지와 재설치 홈 화면 파일 없음이라는 관찰의 배경 근거이며, 사용자의 OS에서 실제 삭제가 수행됐다는 증명이나 모든 버전의 수명 보장은 아니다.

확인한 공식 자료에서 사용자 OS의 ‘북마크 삭제’ 메뉴와 PLAN의 ‘완전 삭제’를 직접 동일시할 근거를 확보하지 못했다. 그 사실을 일반적인 삭제 실패나 저장소 정책 실패로 판정하지 않는다. 사용자 보고된 동작 성공과 화면·삭제 조작 증거 보완을 구분한다.

기존 orchestrator(Socrates, gpt-6.1-sol/medium), worker(Helmholtz, gpt-6-luna/max), critic(Nietzsche, gpt-6.1-sol/medium)을 설정을 바꾸지 않고 재사용하는 순서로 판정 문서를 준비·검토한다. 기존 역할·ID 대응은 실행 상태 문서를 따른다.

## 문서 판정 검증

orchestrator의 완료 조건 정리 → worker의 T09·T08·실행 상태 문서 정합화 → critic의 PLAN·SPEC·증거 원문 독립 대조 순서로 진행했다. critic은 문서 검토 PASS로 판정했다. 이는 T09 기능 이전 게이트 통과 판정이 아니다. 실제 사용자 보고를 보존하면서 증거 미수신·삭제 조작 대응 미확정을 분리했고 전체 반복·PC 추가 생성·특정 403 시험은 요구하지 않았다.

문서 상대 링크 34개와 `git diff --check`는 종료 0. 코드·빌드·배포 산출물을 변경하지 않았으며 기능 테스트를 새로 실행한 것으로 보고하지 않는다. 새로운 실제 API 쓰기·OPFS 쓰기·삭제·main 통합·게시도 수행하지 않았다.
