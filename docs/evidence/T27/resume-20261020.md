A semantic Location double reproduces the missing document load. The earlier native product freeze's exact phase was not captured, so its historical cause remains unconfirmed between these paths.

## Source changes

- `pwa/sw.js`: a restarted worker queries each scoped client's owned generation/phase through `recover`, then explicitly aborts only the reported generation. The inquiry itself never thaws a page. A stale inquiry/abort cannot clear an unrelated newer generation. Active recovery with an outstanding document transition performs a new all-client prepare/lock/recheck/commit, then finishes activate/navigation directly; it does not call `skipWaiting()` on an already active worker. A late active retry without a stale transition only probes/reconciles and never starts a frozen install transaction. An activation with missing global commit evidence enters this recovery path instead of returning and stranding the pages.
- `pwa/platform/update-coordinator.mjs`: recovery reports only the same source instance's session; another registered worker cannot claim its generation. Active preparation requires the explicit active-transition mode. The committed watchdog requests an explicit worker decision while retaining the acknowledged freeze/lock; elapsed time alone never releases either. Recovery retains the active transition intent so a dirty/pending product can defer navigation and retry when clean. Existing generation tombstones and serialized freeze/thaw remain.
- `pwa/platform/app-lifecycle.mjs`: controller/lifecycle notifications can reach the active recovery owner when there is no waiting worker. The guarded final navigation uses `location.reload()` so a hash route receives a new Document while retaining its URL. This call remains behind the committed, active-owner, clean/journal checks; lifecycle notifications do not unconditionally reload.
- `test/pwa-lifecycle-recovery.test.mjs`: nine additional tests combine the actual UI controller and lifecycle/T14 modules with injected native API doubles and VM worker globals. They cover two-client restart recovery, late active retry, waiting restart, worker-instance isolation, unresolved-journal preservation, watchdog ownership, hash routes, dirty-after-recovery retry, and a newly loaded client alongside a committed older client.

No app/domain API signature or `createAppLifecycle` option/method changed in this follow-up. Internal wire additions are `recover`, `ownedGeneration`, `phase`, `needsTransition`, and `activeTransition`. The internal coordinator's notification return carries the recovery owner to the lifecycle wrapper. No `app.mjs`, UI file, build/checker file, `APP_FILES` entry, or parent browser artifact was edited by this follow-up. No new module, agent, commit, merge, publication, or real Notion request was made.
