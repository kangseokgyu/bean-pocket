## P2: 모바일 저장 바가 뷰포트 대신 전체 페이지 아래에 배치됨

- 변경 위치: `pwa/styles.css:1657` (`.brew-run-actions`). 기존 상호작용 위치: 같은 파일 81~83행의 `[data-pull-state]` transform.
- 재현: 기존 `scripts/browser/server.mjs`를 후보 체크아웃에서 실행한다. CUA 브라우저를 390×844로 설정하고 `/candidate/pwa/index.html#/records`를 연다. fixture 1건의 `이 조건으로 다시 추출`을 누른다. 추출 화면 첫 화면에서 `추출 평가 저장`과 취소 바가 보이지 않는다. 조건을 펼치면 저장 바 위치가 긴 페이지 아래로 더 밀린다.
- 실측: 접힌 상태 `.brew-run-actions` rect = `{x:24,y:965.59375,width:327,height:66,bottom:1031.59375}`. 뷰포트 높이는 844. computed position은 `fixed`, bottom은 `76px`이나 화면 밖이다. 조상 `.page`의 computed transform은 `matrix(1, 0, 0, 1, 0, 0)`이다. 펼친 상태에서는 top `2421.84375`, bottom `2487.84375`도 관찰했다.
- 원인: `.page[data-pull-state]`의 transform이 fixed 자손의 containing block을 만든다. 새 저장 바는 그 내부에 있으므로 뷰포트를 기준으로 고정되지 않는다.
- 영향: 눈에 띄고 스크롤 중에도 도달 가능한 모바일 저장 액션이라는 완료 조건이 충족되지 않는다. 저장 기능 자체는 locator의 자동 스크롤 후 실행할 수 있었다.
- 수정 방향: 저장 액션이 변형된 조상의 영향을 받지 않게 배치하거나, 실제 스크롤 구조에 맞는 고정 방식을 선택한다. pull-to-refresh를 유지하면서 접힘·펼침 양쪽에서 저장 바의 실제 rect가 844px 화면과 하단 내비게이션 사이에 드는지 확인한다.
- 테스트 공백: 새 UI 테스트는 CSS 문자열의 `position: fixed`만 검사한다. 브라우저의 실제 containing block과 위치는 검사하지 않아 이 문제를 발견하지 못한다.

CUA AX 트리 및 스크린샷에서 재현을 두 번 확인했다. 스크린샷은 도구 출력에 있으며 파일로 저장하지 않았다. 모든 GUI 조작과 DOM 측정은 `cua_repl`만 사용했다.
