추출 조건 탐색 흐름

공용 레시피는 시작점이다. 한 번의 추출에서 실제로 쓴 조건을 기록으로 보존하고, 같은 원두의 결과를 비교한 뒤 좋은 조건만 다시 쓸 레시피로 남긴다.

1. 조건을 조정하고 실제 결과 저장

1

시작점 선택

공용 레시피 또는 같은 원두의 이전 추출 기록을 고른다. 이전 기록에서 시작하면 당시 스냅샷을 읽는다.

pwa/ui/controller.mjs · loadRoute
2

이번 추출 조건

도징·분쇄·온도·물 양·가이드·붓기 단계를 바꾼다. 첫 단계 0초, 시간 증가, 물 합계 검증을 유지한다.

pwa/ui/view.mjs · renderBrewRun, brewPayload
3

기록 당시 전체 스냅샷

원두, 실제 조건과 단계, 출처 레시피·기록을 저장한다. 조정값을 다시 읽은 공용 레시피로 덮지 않는다.

lib/domain.mjs · createActualSnapshot pwa/commands/index.mjs · prepareBrew

2. 비교하고 다음에 쓸 조건 선택

4

같은 원두 기록 두 건 비교

새 추출과 출발 기록을 기본 쌍으로 연다. 유효한 요청 쌍의 원두를 선택하고 목록 밖 기록은 ID로 직접 읽는다. 비교 원두 목록은 전체 불러온 원두를 유지하고, 추이 차트만 최근 3종으로 제한한다. 이후 원두와 두 기록 선택을 자유롭게 바꾼다.

pwa/ui/controller.mjs · includeComparisonPair pwa/ui/records-insights.mjs · compareBrewRecords
5

기록에서 다시 시작

재추출은 공유 레시피를 다시 읽지 않고 저장된 실제 조건을 사용한다. 출처 레시피가 없어도 기록 스냅샷으로 시작할 수 있다.

pwa/ui/view.mjs · replay-record, recipeFromRecord
6

베스트 또는 공용 레시피 저장

사용자 베스트는 별점 최고 기록과 별도다. 기록을 베스트로 지정하거나 실제 조건을 공용 레시피로 저장하는 작업은 서로 독립적이다.

pwa/commands/index.mjs · prepareBestRecord pwa/ui/view.mjs · actualRecipeForSharedLibrary

데이터 계약

스냅샷 호환

새 v3 실제 조건 스냅샷은 출처가 없는 null도 허용한다. v1/v2 기록과 `bagless-v1` 세대 판독을 유지하고 관계 ID 불일치는 거부한다.

베스트 관계

beans에서 records를 가리키는 one-way relation을 쓴다. 앱은 관계가 0개 또는 1개인지 검증하고 불가 상태를 구분한다.

레시피 통계

“이 레시피에서 시작한 추출 평가”를 세며 조건이 서로 같다고 가정하지 않는다.

문서의 링크는 로컬 작업 트리의 실제 소스 파일을 가리킨다. 이 파일은 네트워크 연결이나 외부 라이브러리 없이 연다.
