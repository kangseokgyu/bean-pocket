Brew search keeps its input mounted

The brew selection search uses the input's current value as the active query. Search responses update the result area while the focused input and its surrounding route nodes stay in place.

1

Read input

content handles input and composition events. The 250 ms timer captures the query and route.

2

Load options

loadSearchOptions keeps its existing route, connection, and request generation checks.

3

Check active query

setSearchOptions ignores a response whose query differs from the mounted input or arrives during composition.

4

Replace results only

renderBrewOptionResults builds cards, empty states, and paging controls inside the existing result wrapper.

Same selection route and connection

refreshBrewOptionResults updates only the result wrapper. The input, its ancestors, value, and focus remain attached.

Route or connection changes

The full renderCurrentContent path remains active so the next screen gets fresh route and connection state.
