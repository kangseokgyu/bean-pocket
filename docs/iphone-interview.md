# iPhone 실행과 Notion 데이터 관리 인터뷰

날짜: 2026-10-17. 상태: 사용자 Q24 답변 「예」로 GitHub Pages PWA 방향 확정. 이 문서는 인터뷰에서 정한 목표이며 구현·배포·실기기 검증 완료 보고가 아니다.

## 확정한 사용 방식

- 개인용 커피 레시피 북을 GitHub Pages의 HTTPS 정적 사이트로 배포한다. iPhone은 Safari에서 홈 화면에 추가해 PWA로 사용하고 PC도 같은 주소에 접속한다.
- PC 서버를 켜지 않고 집 밖 셀룰러 환경에서도 사용한다. 로컬 서버는 개발·검증에 활용할 수 있다.
- 네이티브 iPhone 앱, Xcode 설치·서명, TestFlight, Cloudflare Pages와 별도 서버리스 API는 이번 경로에 포함하지 않는다.
- 조회·신규 추가·레시피 복사는 인터넷 연결을 전제로 한다. 오프라인 데이터 조회·작성·동기화와 추출 타이머는 이후 범위다.
- 첫 배포는 무료 범위에서 진행한다. 유료 전환은 별도로 결정한다. GitHub Free의 Pages는 공개 저장소 조건이 있으므로 실제 계정·저장소 조건을 준비 단계에서 확인한다. 저장소 공개 전환을 임의로 수행하지 않는다.

## 데이터와 기능

- 기존 Notion DB 5개(원두·원두 봉지·레시피·물 붓기 단계·추출 기록)를 원본 저장소로 사용한다. 운영 DB를 중복 생성하지 않는다.
- 기존 조회·신규 추가·레시피 복사를 유지한다. 저장된 항목의 수정·오기 정정·삭제 UI와 API는 추가하지 않는다. 저장 전 양식의 입력값 변경은 가능하다.
- 새로운 추출 조건은 기존 레시피를 복사해 별도 레시피로 저장한다. 과거 추출 기록에 보존한 당시 조건과 물 붓기 단계는 유지한다.
- 앱 시작·새로고침 버튼·저장 성공 후에 Notion 데이터를 재조회한다. 주기적 자동 동기화는 추가하지 않는다. Notion에서 직접 변경한 내용도 다음 조회에 반영한다.
- 관계가 삭제되거나 불일치하면 저장 직전 검증으로 잘못된 관계의 저장을 막고 재조회·확인을 안내한다. 외부에서 변경된 원본을 앱이 자동 수정하지 않는다.

## 노션 연결과 기기 보관

- PWA에서 Notion API에 직접 통신한다. 별도 앱 로그인이나 계정별 데이터 분리는 구현하지 않는다.
- 노션 내부 연결 API 토큰과 필요한 연결 설정을 각 기기에서 입력한다. 토큰은 저장소·배포 파일·URL·로그·Service Worker 앱 파일 캐시에 포함하지 않는다.
- 토큰은 앱 전용 파일에 보관하고 재실행 시 읽어 자동 연결한다. PWA의 파일 보관 후보는 OPFS다. 파일 앱·다운로드 파일로 내보내는 방식은 사용하지 않는다.
- 앱 자체 암호화·보관용 암호 설정·암호 입력·잠금·잠금 해제는 모두 제외한다. 과거에 논의한 30분 자동 잠금도 제외한다.
- 해당 설치의 앱을 삭제하면 토큰·연결 설정도 삭제되어야 한다. Notion 원본, 다른 기기의 저장값, Notion에서 발급한 토큰 자체를 삭제하거나 폐기하는 것은 아니다.
- PWA 삭제와 OPFS 정리의 연동은 아직 검증되지 않았다. iPhone 12 / iOS 27.0.1에서 삭제·재설치 후 토큰이 남지 않는지를 필수 완료 조건으로 둔다. 실패하면 조건을 충족했다고 보고하지 않고 사용자와 대안을 정한다. 네이티브 앱으로 임의 전환하지 않는다.
- Safari, 홈 화면 PWA와 PC 사이에 저장소가 공유된다고 가정하지 않는다. 기기 저장소가 소실되면 토큰을 재입력해 Notion 원본에 다시 연결한다.

## 설치와 업데이트

- GitHub Pages 주소를 Safari로 열고 홈 화면에 추가한다. iOS 앱 서명과 주기적 재설치는 필요하지 않다.
- 배포와 업데이트는 검증된 정적 산출물을 GitHub Pages에 게시하는 방식으로 진행한다. 실제 저장소·게시 소스·수동 게시 절차는 준비 단계에서 확인한다.
- 사용자가 요청한 ‘직접 업로드’는 최종 GitHub Pages 선택에 맞춰 정적 사이트 파일을 게시하는 의미로 정리한다. 아이폰으로 iOS 앱 패키지를 업로드하는 경로는 폐기했다.
- 앱 내부 업데이트 알림·버튼은 추가하지 않는 안이다. 새 배포 후 브라우저 캐시·Service Worker로 구버전이 계속 실행되지 않도록 구성하되 저장 중 강제 교체하지 않는다. 미저장 입력이 사라지지 않게 전환을 지연한다. 토큰·설정은 일반 업데이트 때 유지해야 한다. 구체적인 클라이언트 갱신 시점은 구현 전 확인할 사항이다.

## 저장 실패와 검증

- 연속 탭·반복 제출을 방지하고 작업 상태를 보관한다. Notion 생성 결과를 알 수 없는 경우 자동 재전송하지 않고 ‘저장 여부 확인 필요’로 표시한다.
- 레시피와 단계의 부분 저장은 가능한 범위에서 복구하고 결과 불확실성을 숨기지 않는다. 기기에 보관한 키만으로 모든 기기 간 중복이 방지된다고 가정하지 않는다.
- 실제 iPhone 검증은 운영 DB와 별개인 테스트 DB에서 조회·추가·레시피 복사·재조회부터 확인하고, 통과 후 기존 DB에 연결한다. 테스트 DB 생성·실제 쓰기는 아직 수행하지 않았다.
- 검증 기기는 사용자가 지정한 iPhone 12 / iOS 27.0.1이다. 기기에 직접 연결해 OS나 동작을 확인한 결과는 아니다.

## 구현 전 기술 확인과 완료 기준

1. 토큰을 내장하지 않은 최소 HTTPS PWA에서 iPhone Safari·홈 화면 모드의 Notion 조회·생성·오류 응답을 확인한다.
2. 토큰 파일의 보관·종료·재실행·완전 삭제·재설치를 확인한다. 재설치 후 연결 설정과 토큰이 없어야 하며, Notion 원본은 남아야 한다.
3. 위 두 조건이 충족되면 서버의 관계 검증·스냅샷·중복 및 부분 저장 처리를 브라우저에 이전한다. 동작 변경은 테스트의 의도한 실패를 먼저 확인한 뒤 구현한다.
4. manifest·아이콘·Service Worker·상대 경로와 GitHub Pages 프로젝트 하위 경로를 구성한다. 앱 파일만 캐시하고 노션 응답·토큰은 앱 파일 캐시에 넣지 않는다.
5. PC가 꺼진 상태의 셀룰러망에서 조회·추가·복사를 완료한다. 업데이트 후 저장값 유지와 삭제·재설치 후 저장값 부재도 확인한다.
6. 모의 API 자동 테스트와 실제 iPhone·Notion 검증을 구분해 기록한다. 실제 검증을 하지 못한 항목은 미검증으로 남긴다.

실제 GitHub 저장소·계정 조건, 게시 방식과 클라이언트 업데이트의 안전한 적용 시점은 구현 준비에서 확정해야 한다. 아직 원격 설정·저장소 공개 전환·사이트 게시·앱 코드 변경은 하지 않았다.

## 결정 경위

- Q1~Q7: 개인용·PC 독립·외부 네트워크·온라인 사용·PC 지원을 선택했다. 조건 변경은 새 레시피로 구분했다.
- Q8~Q11: 직접 통신 PWA·무료 범위·삭제 제외를 선택했고, 기존 항목 수정도 미구현 유지로 확정했다.
- Q12~Q18: 로그인 제외·응답 불명 쓰기 재전송 금지·별도 테스트 DB를 선택했다. 암호화와 암호 입력을 제외한 뒤, 토큰 파일 보관·앱 삭제 시 제거·잠금 해제 미구현을 지정했다. 기기는 iPhone 12 / iOS 27.0.1이다.
- Q19~Q21: 데이터 갱신 시점을 확정했다. Cloudflare 직접 업로드를 잠시 선택했으나 이후 직접 설치를 검토했고, 최종적으로 GitHub Pages PWA로 변경했다.
- Q22~Q23: Xcode 설치·서명과 로컬 PC 웹 제안은 최종 방향 변경으로 폐기했다.
- Q24: 사용자가 GitHub Pages PWA 방향에 ‘예’라고 답했다. 현재 결정은 [ADR-0003](adr/0003-github-pages-personal-pwa.md)을 따른다.

[기존 독립 실행 계획](iphone-standalone-plan.html)의 암호화·잠금 제안은 이번 확정 범위와 다르므로 현재 요구사항으로 취급하지 않는다. [현재 입력·저장 방식 설명](current-editing-overview.html)은 기존 구현의 정적 확인 결과다.

## 근거와 검증 상태

- [GitHub Pages 소개](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages): 정적 호스팅, 프로젝트 주소, 저장소 요금제 조건.
- [GitHub Pages HTTPS](https://docs.github.com/en/pages/getting-started-with-github-pages/securing-your-github-pages-site-with-https): HTTPS 제공.
- [Notion 공식 SDK 브라우저 사용](https://github.com/makenotion/notion-sdk-js#browser-usage): CORS와 브라우저 토큰 사용 조건.
- [WebKit OPFS](https://webkit.org/blog/12257/the-file-system-access-api-with-origin-private-file-system/): 출처별 비공개 파일 저장소. 홈 화면 앱 삭제 연동은 실기기 미검증이다.
- [WebKit 저장소 정책](https://webkit.org/blog/14403/updates-to-storage-policy/): 저장소 정리와 영속성 요청.

현재 코드는 Node 서버를 통한 조회·신규 등록을 지원한다. 이번 인터뷰에서는 파일 읽기와 문서 작성·검사만 수행했고 실제 앱·Notion·삭제 동작 테스트는 실행하지 않았다. 설명을 위해 기존 코드의 동작을 확인했으며 구현 완료를 주장하지 않는다.

첫 라운드 검토는 orchestrator Einstein(gpt-6.1-sol / medium) → worker Helmholtz(gpt-6-luna / max) → critic Fermat(gpt-6.1-sol / medium) 순서로 수행했다. 도구는 역할명 지정을 지원하지 않아 역할과 자동 별칭을 대응했다. 이후 단순 답변 기록과 문서 갱신은 본 에이전트가 직접 수행했다.
