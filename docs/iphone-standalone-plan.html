01 / DECISION

가능합니다. 실행용 백엔드를 없애는 방식입니다.

권장 구성: HTTPS 정적 웹사이트 + 홈 화면 PWA + 브라우저의 Notion REST API 직접 호출

PC에서 node server.mjs를 켜둘 필요가 없어집니다. 정적 호스팅은 HTML·JS·CSS를 배포하고 업데이트하는 역할만 맡습니다. 노션 조회·저장은 아이폰에서 노션으로 직접 전송합니다.

최신 노션 공식 SDK 문서는 API의 CORS 지원과 브라우저 직접 호출을 안내합니다. 다만 SDK는 토큰의 브라우저 사용을 기본 차단하므로 SDK를 도입하면 명시적 허용이 필요합니다. 현재 프로젝트의 REST fetch 구현을 재사용하면 SDK 도입은 필요하지 않습니다. 실제 iPhone·배포 출처에서의 동작은 첫 기술 검증으로 확인합니다.

우선안

개인용 PWA

Safari에서 주소 열기 → 홈 화면에 추가 → 앱처럼 실행. 기존 화면을 활용하고 백엔드 운영을 없앱니다.

최초 설치·업데이트는 정적 호스팅에 접근. 실시간 노션 연결에는 인터넷 필요.

조건부 대안

iOS 앱으로 묶기

파일 배포처에도 의존하지 않는 설치 패키지가 꼭 필요하면 Capacitor와 네이티브 HTTP·Keychain을 검토합니다.

Mac·Xcode·서명·기기 배포 및 업데이트 관리 필요. 단순 WebView 포장만으로 네이티브 통신·보안 저장이 생기지는 않음.

별도 요구사항

완전한 오프라인

인터넷 없이 노션의 최신 데이터를 읽거나 저장할 수는 없습니다. 최근 데이터 조회는 기기 캐시로 확장할 수 있습니다.

오프라인 입력·자동 동기화는 별도 단계로 분리. 1차 버전은 온라인 저장에 집중.

“서버 없이”의 정확한 범위
  • 내 PC·별도 API 서버 없이: 권장 PWA로 충족할 수 있습니다.
  • 설치 후 정적 호스팅에 연결되지 않아도 실행: Service Worker 캐시가 유지되고 설치가 완료됐다면 화면을 열 수 있습니다. 저장소 삭제·재설치 때는 다시 다운로드해야 합니다.
  • 최초 실행부터 어떠한 파일 서버도 사용하지 않기: 네이티브 앱 패키지 배포를 검토해야 합니다.
  • 노션 서버에도 연결하지 않기: 로컬 데이터만 사용할 수 있으며 실시간 노션 연동과는 양립하지 않습니다.

file:// HTML을 파일 앱에서 여는 방식은 모듈·출처·PWA 설치 제약 때문에 운영 경로로 삼지 않습니다. 이 설명용 HTML 자체는 외부 라이브러리 없이 열립니다.

기기 안에 보관

  • Cache API: 버전이 정해진 앱 파일만.
  • IndexedDB: 암호화한 토큰과 연결 설정.
  • 메모리: 잠금 해제 중인 토큰과 조회 데이터.
  • IndexedDB: 중복 제출·부분 저장 확인용 작업 상태. 토큰과 민감한 본문은 로그에 넣지 않기.

노션 연결 후 실행 순서

  1. 암호로 저장된 토큰 잠금 해제.
  2. 5개 데이터 소스의 권한·속성 확인.
  3. 페이지네이션으로 데이터를 끝까지 조회.
  4. 원두·레시피·단계·기록을 관계 ID로 결합.
  5. 원두 목록 → 레시피 → 추출 방법·평가 표시.
저장 흐름

입력 검증 → 최신 관련 데이터 확인 → 추출 당시 조건 생성 → 노션 저장 → 결과 재조회 → 성공 표시. 기존 서버의 업무 규칙까지 브라우저로 옮겨야 합니다.

기존 DATA_SOURCES의 5개 ID와 속성 매핑을 재사용합니다. 토큰 교체 시 이전 조회 데이터·진행 상태를 연결별로 격리하고 새 연결 검증이 끝난 뒤 전환합니다. ID가 공개되는 것과 접근 권한이 생기는 것은 별개이며, 실제 권한은 노션 토큰과 공유 설정이 결정합니다.

03 / CREDENTIALS

토큰은 한 번 입력하고, 기기에서 잠금 해제합니다.

권장 기본값은 암호화 보관입니다. 토큰을 매번 붙여 넣지 않되, 재실행할 때 저장용 암호로 잠금을 해제합니다. 계정 가입은 추가하지 않습니다.

  1. 노션에서 레시피 북 전용 내부 연결을 만들고 해당 페이지와 필요한 하위 DB만 공유합니다. 읽기·삽입·수정 권한은 기존 저장·복구 동작에 맞춥니다.
  2. 아이폰에서 토큰과 저장용 암호를 입력합니다. 연결이 검증된 뒤 저장합니다.
  3. Web Crypto의 PBKDF2로 암호에서 키를 유도하고 AES-GCM으로 토큰을 암호화합니다. 무작위 salt·매 암호화마다 새 IV·알고리즘 버전을 암호문과 함께 IndexedDB에 보관합니다. 반복 횟수는 대상 아이폰 성능을 확인해 정합니다.
  4. 암호·복호화 키는 영구 저장하지 않습니다. 닫기·수동 잠금·설정한 비활성 시간 후 메모리 참조를 해제하고 다시 잠급니다.
  5. 연결 해제 시 토큰과 연결별 로컬 데이터를 삭제합니다. 암호를 잊으면 저장본을 지우고 토큰을 다시 입력합니다.

자동 열기와 비밀 보관 사이의 선택

암호화해도 실행 중의 토큰은 같은 출처의 코드가 사용할 수 있습니다. 키까지 함께 저장하는 “완전 자동 잠금 해제”는 토큰 탈취 방어 효과가 제한적입니다. 기본안은 암호 입력이며, Face ID·Keychain 중심의 자동 해제가 핵심이면 네이티브 앱 경로를 별도 설계합니다.

토큰을 소스·URL·정적 파일·서비스 워커 캐시·로그에 포함하지 않습니다. 노션의 텍스트는 HTML로 신뢰하지 않고 이스케이프합니다. 외부 CDN 스크립트·분석 도구를 배제하고 CSP는 connect-src 'self' https://api.notion.com 등 필요한 출처만 허용합니다. 정적 호스팅 계정과 배포 코드의 통제도 토큰 보호의 일부입니다.

개인 사용을 전제로 한 절충안입니다. 여러 사람에게 배포하는 서비스로 확장할 경우 공유 토큰을 웹에 싣지 않고 별도 인증 구조를 검토합니다. 암호화는 이 계획의 설계 제안이며 현재 구현된 기능이 아닙니다.

04 / CODE MIGRATION

현재 코드에서 무엇을 옮길 것인가.

확인한 현재 코드현재 역할계획한 변경
public/app.jsapi()·loadData()가 /api/* 호출. 원두·레시피·기록 렌더링.화면은 재사용하고 연결·조회·저장은 브라우저용 서비스로 호출. 초기 /api/status 의존도 제거. 잠금·온라인·실패 상태를 표시.

기존 버전 헤더를 유지해 이전과 API 버전 변경을 분리합니다. 해당 버전의 지원·필요한 엔드포인트는 구현 시 확인합니다. mode: 'no-cors'는 응답을 읽을 수 없어 대안이 아닙니다.

가장 주의할 이전 항목: 중복 저장과 부분 저장

현재 서버의 Idempotency-Key 처리와 메모리 Map은 노션 자체의 보장이 아닙니다. 브라우저에 전송 전 작업 상태와 확인된 페이지 ID를 보관하고, 앱 재실행 시 미완료 작업을 먼저 확인해야 합니다. 응답이 유실된 생성 요청은 결과를 모르면 자동 재전송하지 않습니다. 같은 날짜·같은 레시피라는 이유로 별개의 추출 기록을 합쳐서도 안 됩니다.

레시피와 여러 단계 저장 중 실패하면 확인된 생성 페이지의 보관 처리를 시도합니다. 보관 처리 실패·응답 유실은 “확인 필요”로 남깁니다. 로컬 상태만으로 기기 간 중복이나 모든 불확실성을 해결할 수는 없으며, 자동 복구까지 원하면 노션에 작업 ID·완료 상태를 추가하는 스키마 변경을 별도 검토합니다.

05 / DELIVERY PLAN

연결 가능성부터 확인하고, 작은 단계로 이전합니다.

0. 기술 확인
첫 번째 통과 조건

실제 iPhone에서 직접 읽고 쓰기

토큰을 내장하지 않은 작은 HTTPS 테스트 페이지에서 Authorization·Notion-Version·JSON 헤더를 사용합니다. Safari와 홈 화면 모드에서 preflight, 데이터 소스 조회, POST query를 확인합니다. 쓰기 검증은 분리된 테스트 데이터에서 생성·재조회·보관 처리까지 확인합니다.

통과: 프록시 없이 필요한 GET·POST·PATCH 응답을 읽음. 실패: 출처·헤더·권한·브라우저를 구분해 진단하고, API CORS 제약으로 확정되면 네이티브 HTTP 대안으로 전환. 현시점 실제 기기 검증은 미수행.

1. 서비스 이전
현재 기능 유지

서버의 저장 규칙을 브라우저 서비스로 이동

동작 테스트를 먼저 작성해 새 경계에서 의도대로 실패하는지 확인합니다. 이후 조회·원두·봉지·레시피 복사·단계 저장·추출 기록을 이전합니다. 기존 관계 검증과 스냅샷 보존을 유지합니다.

통과: 브라우저에서 기존 사용자 흐름 완료. 실행 중 /api/* 요청 없음. 기존 도메인·노션 테스트와 이전된 사용자 흐름 테스트 통과.

2. 토큰·실패 처리
재실행 가능하게

암호화 저장과 작업 상태 복구

암호 잠금·연결 교체·연결 해제를 구현합니다. 쓰기 직전 작업을 기록하고 확정·확인 필요 상태를 구분합니다. 401·403·404·429 및 통신 실패를 사용자 상태로 처리합니다. 요청 큐와 상한 있는 재시도 정책을 두고, 429는 노션의 대기 안내를 따릅니다. 응답 불명인 쓰기는 자동 반복하지 않습니다.

통과: 앱을 닫았다 다시 열어 토큰 재입력 없이 암호로 연결. 저장 도중 종료·잘못된 암호·취소·저장소 오류 테스트에서 중복과 거짓 성공 표시 방지.

3. PWA 배포
아이폰에서 독립 실행

홈 화면 설치와 앱 파일 캐시

완성된 정적 산출물만 HTTPS 호스팅에 배포합니다. manifest와 아이콘을 제공하고 Service Worker는 앱 파일만 버전별 캐시합니다. 설치 파일 전체가 준비된 뒤 오프라인 준비 완료를 표시합니다. 노션 API와 토큰은 Cache API 대상에서 제외합니다.

통과: PC 서버를 켜지 않고 휴대전화 통신망에서 조회·저장. 기존 버전 사용 중 새 배포가 생기면 저장 작업 종료 후 업데이트. 하위 경로·처음 방문·재설치·캐시 삭제도 확인.

4. 선택 확장
1차 완료 후

최근 레시피의 오프라인 조회

노션 원본은 유지하고 최근 조회 데이터를 기기에 암호화 저장하는 옵션을 추가합니다. 비행기 모드에서 마지막 조회 시각과 “이전 데이터” 표시 후 읽기만 허용합니다. 오프라인 작성·백그라운드 동기화는 별도 요구사항으로 남깁니다.

브라우저 저장소는 영구 보존이 보장되지 않습니다. navigator.storage.persist() 요청 결과를 확인하고, 삭제됐을 때 재연결·재조회할 수 있게 합니다. Safari와 홈 화면 간 저장소 공유도 가정하지 않습니다.

기간은 0단계 결과와 암호화·복구 범위 확인 후 산정합니다. 1차 완료 범위는 0~3단계이며 4단계는 선택입니다.

06 / ACCEPTANCE

“독립 실행 완료”의 확인 기준.

상황기대 결과
PC 서버를 사용하지 않고 iPhone 셀룰러망에서 실행정적 배포 주소 또는 홈 화면 아이콘으로 열리고 노션 원두·레시피 표시. API 통신 대상은 api.notion.com.
최초 연결 후 앱 종료·재실행저장용 암호로 해제. 토큰 다시 붙여 넣기 불필요. 잘못된 암호는 연결·복호화를 허용하지 않음.
원두 → 봉지 → 레시피·단계 → 추출 기록노션 저장 후 재조회해 데이터·관계·단계·별점·스냅샷 확인. 기존 복사 독립성·과거 조건 보존 시나리오 유지.
저장 버튼 연속 탭·통신 끊김·저장 중 앱 종료확정된 작업은 결과를 재사용. 불확실한 생성은 자동 재전송하지 않고 확인 필요 표시. 동일 날짜의 독립 기록은 각각 허용.
부분 저장·권한 철회·잘못된 토큰·요청 제한거짓 성공 없음. 가능한 복구 및 재연결·대기 안내. 401/403/404/429와 네트워크 오류를 구분.
앱 파일 설치 완료 후 비행기 모드화면과 설정은 열림. 1차 버전의 노션 조회·저장은 연결 필요 표시. 선택 캐시 확장 시에만 최근 레시피 읽기 제공.
로컬 저장소 삭제·용량 부족·배포 주소 변경데이터가 보존됐다고 오표시하지 않음. 토큰 재입력·재연결 안내. 노션 원본으로 복구. 다른 출처로 토큰이 자동 이동하지 않음.
정적 산출물·앱 캐시·로그 검사토큰·암호·복호화 키가 포함되지 않음. 노션 텍스트가 스크립트로 실행되지 않음. 업데이트가 저장 작업을 중단하지 않음.

검증은 모의 API를 이용한 자동 테스트와 실제 iPhone·테스트용 노션 데이터에서의 확인을 구분해 기록합니다. 기존 test/http.test.mjs의 서버 요청 전용 검증은 새 브라우저 서비스와 공개 사용자 흐름에 맞게 옮기고, test/domain.test.mjs·test/notion.test.mjs의 유효한 규칙 검증은 재사용합니다.

07 / EVIDENCE

근거와 아직 확인할 부분.

현재 코드에서 확인: server.mjs, lib/notion.mjs, lib/domain.mjs, public/app.js, public/submission.mjs, public/index.html, package.json, 테스트 파일과 SPEC.md의 검증 기준.

문서에는 구현 이전 설명이 일부 남아 있어 현재 동작 판단은 실행 코드를 우선했습니다. 기존 스펙의 서버 토큰 관리·오프라인 제외는 이번 요청에 따라 변경 검토할 항목입니다. 앱 구현 때 스펙·README도 갱신합니다.

  1. Notion 공식 JavaScript SDK — Browser usage: 브라우저 CORS, 토큰 사용의 제약, SDK의 명시적 허용 옵션. OAuth 토큰 교환은 별도 서버가 필요하므로 이번 개인용 토큰 방식에서 제외.
  2. Notion — Internal connections: 토큰 발급, 페이지 공유, 연결 권한.
  3. Notion — Request limits: 요청 제한, 대기 안내, 재시도와 쓰기 결과 불확실성 처리.
  4. MDN — Service Worker API: HTTPS 보안 문맥과 오프라인 앱 파일 제공.
  5. MDN — SubtleCrypto.deriveKey(): PBKDF2와 대칭 암호 키 유도.
  6. WebKit — Updates to Storage Policy: 기기 저장소 삭제 가능성과 영속성 요청.
  7. Capacitor — Http: 네이티브 HTTP가 필요한 대안 경로의 근거.

개인용 PWA, 직접 REST 호출, 토큰 암호화 저장, 온라인 조회·저장을 1차 범위로 삼습니다. 실제 기기 CORS 확인, 배포 출처 선정, 저장용 암호 사용 경험, 업데이트·저장 복구 검증은 구현 단계에서 확인합니다.
