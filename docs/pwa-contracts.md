# PWA 브라우저 구현 계약 초안 — T10

2026-10-18. 기준은 SPEC.md, ADR-0003, PLAN.md다. 사용자가 선택한 사전 준비로 작성한 **초안**이며 T09 통과 또는 T10 최종 확정을 의미하지 않는다. OPFS는 후보이며 실제 T06·T08 결과에 따라 보관 방식과 통신 가능성을 판정한다. T12 이후 기능 구현은 아직 시작하지 않는다.

## 입력·출력과 경계

- 도메인 원본은 `lib/domain.mjs` 하나다. 빌드가 같은 바이트를 `dist/domain.mjs`로 공급한다. 계산·검증·복사·스냅샷 의미를 변경하거나 소스 사본을 유지하지 않는다.
- 연결 입력은 `{ token, dataSources: { beans, bags, recipes, steps, records } }`다. 브라우저는 환경변수·Node API를 참조하지 않는다. 실제 값은 소스·빌드·URL·앱 캐시·공개 증거에 포함하지 않는다.
- 데이터 소스 응답은 기존 코드의 속성명·타입을 논리 도메인 필드로 변환한다. 필수 관계는 정확히 한 개여야 하며 기록의 봉지는 선택이다. 봉지와 레시피의 원두가 다르거나 참조 대상이 없으면 저장을 차단한다.
- 스냅샷은 기존 `createSnapshot`의 version 1 구조, 조건, 모든 단계 값·순서를 보존한다. 현재 Notion 관계를 따라 과거 조건을 재구성하지 않는다. rich_text 분할·복원은 통신 어댑터의 책임이다.
- 조회 성공은 도메인 배열을 반환하고 실패는 오류를 반환한다. 실패를 빈 목록으로 바꾸지 않는다. 반환한 초안을 바꿔도 원본·조회 캐시와 단계 참조가 공유되지 않아야 한다.

## 작업 상태 6개

| 상태 | 의미 | 후속 동작 |
|---|---|---|
| 미제출 | 입력 초안, 원격 쓰기 전 | 검증 및 취소 가능 |
| 처리 중 | 현재 작업 키로 쓰기 실행 중 | 같은 설치의 중복 탭·다른 창 제출 차단 |
| 성공 | 필요한 모든 쓰기의 성공 응답 확인 | 생성 ID 보존 후 재조회, 재조회 실패를 저장 실패로 바꾸지 않음 |
| 명확한 실패 | 아직 쓰지 않았거나 해당 쓰기가 명확히 거절됨 | 원인 수정 뒤 같은 payload·키의 안전한 재제출 여부 판단 |
| 확인 필요 | 타임아웃·응답 유실·해석 불가·쓰기 5xx 등 | 자동 재전송 금지, Notion 원본 확인과 재조회 전 잠금 유지 |
| 부분 저장 | 일부 쓰기만 성공했거나 내부 취소 실패 | 불완전 항목 제외, 이미 확인된 결과와 불확실 부분을 구분 |

HTTP 400/401/403/404라고 작업 전체가 미저장인 것은 아니다. 앞선 쓰기가 성공했다면 작업은 부분 저장 또는 확인 필요일 수 있다. 부분 취소는 이미 식별자를 확보한 새 페이지에만 적용하고 원본 레시피를 변경하지 않는다.

## 작업 키·동시 창·재실행

- 사용자가 의도한 한 번의 제출마다 작업 키를 만든다. 같은 키는 정규화된 payload 지문 하나에만 대응한다. 단계 순서·제거·물 양 등 의미 있는 입력 변경은 새 payload와 새 키를 만든다.
- 성공한 기록 뒤 사용자가 의도적으로 다시 제출하면 값이 같아도 새 키를 사용한다. 날짜·별점만으로 중복 판정하지 않는다.
- `submission-state` 저장소는 형식 버전, 작업 키, payload 지문, 상태, 확인된 새 항목 ID·결과 요약을 보관한다. 토큰·컵노트 원문·불필요한 전체 payload는 작업 상태 파일에 넣지 않는다.
- 쓰기 전 상태를 보관하고 설치 내 원자적 배타 구역을 획득한다. 상태 보관 또는 잠금에 실패하면 원격 쓰기를 시작하지 않는다. 메모리 버튼 플래그만으로 다른 창을 제어했다고 보장하지 않는다.
- 재실행 때 남아 있는 처리 중 상태는 확인 필요로 복구한다. 사용자가 Notion 원본을 확인했다고 표시하고 재조회가 성공해야 해제를 허용한다. 설정 교체·키 재발급만으로 불확실 작업을 우회하지 않는다.
- 기기 간 전역 중복 방지는 보장하지 않는다. 잠금과 파일 저장의 구체적 지원 방식은 T09 이후 확정하며 지원하지 않는 환경에서는 안전하게 쓰기를 차단한다.

## 연결 교체·보관 파일

새 연결은 필수 설정과 스키마·관계 접근을 먼저 검증하고 파일 보관에 성공한 뒤 활성 연결을 교체한다. 새 검증·쓰기 실패는 기존 유효 연결을 훼손하지 않는다. 저장 진행 중 또는 불확실 작업이 있으면 대상 연결을 임의로 바꾸지 않는다. 연결 파일 부재는 재입력을 안내하며 손상·권한·용량·미지원은 구분한다. 일반 업데이트는 호환 가능한 연결 파일을 유지해야 한다.

OPFS, 파일 형식과 원자적 교체 방법은 아직 확정하지 않았다. T07/T08 실측을 통과한 후보만 T13에 사용한다. localStorage나 외부 다운로드로 대체하지 않는다.

## 재조회와 안전한 업데이트

앱 시작·사용자 새로고침·저장 성공 후 최신 데이터를 조회한다. 주기적 조회나 오프라인 Notion 데이터 저장은 추가하지 않는다. 저장 성공 후 재조회 실패는 “저장은 성공했으나 최신 목록을 불러오지 못함”으로 표시하고 중복 제출을 유도하지 않는다.

새 SW의 적용 조건은 미저장 입력이 없고 현재 실행 중인 저장이 없는 안전 시점이다. 입력·저장 중 강제 새로고침이나 무조건 skipWaiting을 하지 않는다. 새 버전 대기 상태와 저장 상태는 별도로 관리한다. 자동 적용 방법은 T27에서 실제 브라우저로 검증하며 업데이트 버튼·알림은 제품 범위에 추가하지 않는다.

## 모듈과 소유 범위

| 파일 | 책임 / 작성 범위 |
|---|---|
| `lib/domain.mjs` → `dist/domain.mjs` | 도메인 원본과 정적 공급. 통신·파일 부수 효과 없음 |
| `pwa/data/notion-client.mjs` | T12: 주입된 연결로 통신, 페이지네이션·직렬화·오류 변환 |
| `pwa/platform/connection-file.mjs` | T13: 검증된 파일 보관 어댑터 |
| `pwa/state/submission-state.mjs` | T14: 키·상태·잠금·재실행 복구 |
| `pwa/data/read-repository.mjs` | T15: 최신 조회와 관계·완전성 판정 |
| `pwa/commands/create-*.mjs` | 각 생성 명령. UI·공용 파일 직접 수정 없음 |
| `pwa/app.mjs`, `pwa/styles.css` | 화면 연결은 입력 흐름 순서대로 직렬 작업 |
| `scripts/`, workflow, manifest·SW, package.json | 부모 통합 담당자가 변경을 직렬 반영 |

T10 확정 전 남은 결정: 실측에 맞는 잠금·파일 저장 수단, 여러 창과 재실행에서도 불완전 레시피를 숨길 원격 완전성 표식·스키마 호환, 공개 브라우저 흐름 자동 검증 도구. 현재 검증은 Node 단위 테스트·모의 API와 실제 브라우저 확인을 구분해 사용한다. 이 초안을 T10 전체 완료로 표시하지 않는다.
