# PWA 연결·사용·복구 안내

이 안내는 GitHub Pages용 브라우저 앱을 대상으로 한다. 앱 주소는 [bean-pocket](https://kangseokgyu.github.io/bean-pocket/)이며, 2026-10-22 최신 게시 빌드는 `d456a8e837a4`이다. 실제 게시 버전과 검증 상태는 [실행 상태](implementation-status.md)를 확인한다. 로컬 모의 검증과 실제 Notion·실기기 검증을 구분한다.

## 연결과 사용

1. 기기에서 앱을 열고 Notion 통합 토큰과 원두·레시피·물 붓기 단계·추출 기록의 **데이터 소스 ID 4개**를 입력한다. 데이터베이스 ID와 구분한다. 채팅의 Notion 연결은 앱에 전달되지 않는다.
2. 연결 확인과 기기 파일 저장이 모두 성공한 뒤 사용한다. 파일은 해당 브라우저 저장소의 앱 전용 영역에 보관된다. Safari, 홈 화면 앱, PC 사이에 설정이 공유된다고 가정하지 않는다.
3. 원두 탭의 `+` 버튼으로 새 원두 입력을 열어 이름으로 등록한다. 입력 취소·저장 성공 후 폼은 다시 숨겨진다. `↻` 버튼은 최신 목록을 불러온다. 원산지와 농장은 기존 Notion의 `원산지·농장` 항목에 함께 기록한다.
4. 레시피는 특정 원두에 속하지 않는 공용 항목이다. 레시피 단계는 첫 시간 `0:00`부터 증가시키고 단계별 물 양의 합을 총 물 양과 맞춘다. 복사한 초안은 저장 전에 바꿀 수 있다. 저장한 레시피 원본을 수정하거나 삭제하는 기능은 제공하지 않는다.
5. 추출 기록마다 원두와 레시피를 각각 선택하고 날짜와 정수 별점 1~5를 입력한다. 컵노트는 선택이다. 같은 날 여러 번 저장할 수 있고, 기록마다 원두·레시피·평가를 확인하거나 원두별·레시피별로 찾아볼 수 있다. 각 기록에는 당시 원두 정보와 레시피 조건·모든 단계가 보존된다.

기존 개인 설정에 records의 `원두` relation이 없으면 기존 기록은 계속 조회할 수 있지만 새 기록은 전송 전에 차단되고 schema 설정 안내가 표시된다. 최신 앱과 오래된 탭 사이의 이전 journal/payload에 원두 선택이 빠진 경우 자동 보완·재전송하지 않는다. records의 relation을 확장한 뒤 페이지를 새로고침하고 연결을 다시 확인한다. 기존 recipes의 원두 relation은 legacy 판독을 위해 유지한다.

기존 설정을 읽어도 Notion 검증에 실패하면 연결 완료로 표시하지 않는다. 연결 정보와 토큰을 채팅·URL·공개 저장소에 올리지 않는다. 테스트용 연결과 운영용 연결은 명확히 구분한다.

화면 맨 위에서 아래로 당기면 화면이 함께 내려오고 상단에 회색 스피너가 점차 나타난다. 입력 칸·버튼·링크·표 위에서 시작해도 동작한다. 240px 이상 당겼다가 손을 놓으면 스피너가 회전하고 페이지 전체를 다시 로드하므로 저장하지 않은 입력은 사라진다. 당긴 거리를 줄이거나 터치를 취소하면 새로고침하지 않고 화면이 원위치로 돌아온다. 탭·텍스트 입력·가로 스크롤은 기존대로 동작하며, 내부 스크롤 영역이 맨 위가 아니면 해당 영역부터 스크롤한다. 저장·조회 또는 업데이트 적용 중에는 새로고침하지 않는다. 입력을 유지하며 최신 목록만 불러오려면 `↻` 버튼을 사용한다. 기기의 동작 줄이기 설정을 켜면 스피너 회전과 복귀 애니메이션은 생략한다.

기존 연결을 여는 중 다른 창이 저장소를 사용하고 있으면 잠시 기다린다. 계속 기다릴 수 없는 경우 **저장된 연결 다시 읽기**를 누른다. 이 안내만으로 연결 정보를 새로 입력하지 않는다.

## 원두 삭제

원두 카드 오른쪽 위 휴지통 버튼을 누르고 원두명을 확인한 뒤 삭제한다. 취소하면 변경하지 않는다. 삭제는 Notion 휴지통으로 이동하는 방식이며, 연결된 실제 추출 기록이 있거나 원두 관계를 판별할 수 없는 legacy 기록이 있으면 차단한다. 레시피에 남아 있는 legacy 원두 relation만으로는 삭제를 막지 않는다. 관련 항목은 함께 삭제하지 않는다.

삭제 응답을 잃으면 새 삭제 요청을 보내지 말고 Notion 원본에서 대상 원두가 휴지통에 있는지 확인한다. 앱의 원두 삭제 확인에서 **휴지통에 있음** 또는 **삭제되지 않고 남아 있음**을 선택하면 같은 원두의 실제 상태를 다시 읽어 복구한다. 원본을 읽을 수 없으면 쓰기 차단을 유지한다. 삭제 성공 후 목록 조회만 실패했다면 목록을 새로고침한다.

## 실패와 확인 필요

- **입력 오류 또는 명확한 실패:** 안내를 확인해 입력·권한·관계를 바로잡고 명시적으로 다시 제출한다. 자동 재전송은 하지 않는다.
- **저장 여부 확인 필요:** 응답을 잃었어도 원본에는 저장됐을 수 있다. 새 요청으로 우회하지 말고 원래 Notion 대상의 실제 생성 결과를 먼저 확인한다. 앱이 제공하는 원본 확인·정상 재조회 기반 복구만 사용한다.
- **부분 저장:** 레시피나 일부 단계의 저장·취소가 완결되지 않은 상태다. 정상 레시피처럼 사용하지 않는다. 확인되지 않은 ID를 추측해 자동 삭제하지 않는다.
- **저장은 성공했으나 조회 실패:** 저장을 반복하지 말고 목록을 다시 불러온다.
- **설정 저장 확인 필요:** 파일과 작업 기록의 세대가 일치하는지 확인한다. 재입력이나 파일 삭제로 이력을 우회하지 않는다. 원래 대상이나 상태를 확인할 수 없으면 쓰기 차단을 유지한다.

파일 손상·보관 기능 미지원·권한 부족·용량 부족은 빈 설정으로 자동 덮어쓰지 않는다. 설정 파일을 외부로 내보내거나 임의 삭제하는 복구 절차는 제공하지 않는다.

## 설치·업데이트·게시

지정 iPhone에서는 Safari에서 게시 주소를 열고 공유 메뉴의 홈 화면 추가를 사용한다. 홈 화면에서 웹 앱으로 열리는지 확인한다. 최종 앱의 재실행·업데이트·삭제/재설치 수명은 [T29 체크리스트](evidence/T29/README.md)로 확인한다.

업데이트는 미저장 입력·진행 중 저장·미해결 상태가 있는 동안 보류한다. 같은 범위의 다른 창도 영향을 주므로 저장하거나 입력을 취소해 모든 창의 작업을 마무리한다. 안전한 상태가 되면 새 버전을 적용한다. 업데이트 알림·적용 버튼은 제공하지 않는다.

수동 게시와 이전 정상 버전 복귀는 [게시 절차](pages-deploy.md)를 따른다. 게시 대상은 검사에 통과한 `dist/`뿐이다. 토큰·개인 설정 파일을 빌드에 전달하지 않는다. main 통합은 변경과 검증 결과를 제시한 뒤 사용자의 명시적 승인을 받는다.

## 운영 연결 전 조건

테스트 DB의 자동·실기기 검증을 먼저 완료한다. 이후 기존 운영 데이터 소스 4개를 기기에 입력해 읽기를 확인한다. 운영 DB를 새로 만들거나 시험 레코드를 삽입하지 않는다. 운영 쓰기는 사용자가 의도한 실제 등록만 수행한다.

## 기존 운영 연결로 전환

T29 지정 시나리오 확인 후 진행한다. 저장·미해결 작업과 다른 탭의 입력을 마무리한 뒤, 사용할 기기의 ‘Notion 연결 설정’에서 테스트용 값을 기존 운영용 토큰과 데이터 소스 ID 4개로 바꿔 연결 확인·저장한다. 원두·레시피·물 붓기 단계·추출 기록 순서를 맞춘다. 원래 운영 DB를 재사용하고 새 DB를 만들지 않는다.

연결 후 기존 원두·레시피·추출 기록이 조회되는지 확인한다. 레시피를 선택했을 때 기존 단계도 표시되는지 확인한다. 운영 검증용 새 항목을 저장하지 않는다. 각 기기/브라우저의 설정은 별도로 입력하며, 테스트 연결에서 운영 연결로 바꿔도 Notion 원본을 복사·삭제하지 않는다. 기존 토큰·ID는 앱 입력에만 사용한다.

2026-10-21 기존 운영 연결·읽기는 사용자 확인을 완료했다. [최종 인계와 확인 범위](evidence/T30/README.md)를 참고한다. 추가 기기는 위 절차로 별도 연결한다.

현재 기록은 유효한 v2 snapshot의 `recordGeneration: "bagless-v1"`만 표시·집계한다. 숨겨진 과거 기록은 삭제 보호에 남으며, 원두를 확정할 수 없으면 삭제를 차단한다. 봉지 데이터는 조회·추론·이전하지 않고 기존 Notion 행·속성을 그대로 둔다.
