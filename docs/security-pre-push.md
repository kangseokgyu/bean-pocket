# GitHub 업로드 전 보안 점검

점검일: 2026-10-17 (Asia/Seoul). 대상: bean-pocket의 최초 GitHub 업로드 파일 및 기존 로컬 Git 이력.

## 범위와 방법

전체 침투 테스트가 아닌 업로드 전 정적 점검이다. 추적 파일, 기존 커밋 3개(파일 항목 68개), 환경 파일 제외 규칙, 스크린샷 2개와 서버·Notion·브라우저 소스의 신뢰 경계를 검토했다. 토큰·개인키·GitHub/AWS 자격증명·JWT 패턴과 로컬 `.env.local`의 설정값을 비교했다. 실제 값은 보고서나 로그에 기록하지 않았다. 패턴 검색은 모든 종류의 비밀정보 부재를 보장하지 않는다.

## 업로드에 반영한 조치

- 현재 추적 파일에서 점검한 자격증명 패턴 및 실제 로컬 환경설정 값은 발견되지 않았다.
- 과거 커밋 2개에는 개인 Notion 식별자가 남아 있었다. 식별자는 인증 토큰과 다르지만 개인 워크스페이스 정보이므로 기존 이력을 GitHub로 보내지 않는다.
- GitHub에는 점검한 현재 파일만 새 초기 커밋으로 게시한다. 기존 로컬 이력은 별도 로컬 브랜치에 보존한다.
- `.env.local`은 Git에서 제외한다. `.env.example`의 토큰·Notion 식별자 값은 비워 두었다.
- 작업 전부터 미추적 상태였던 `docs/iphone-standalone-plan.html`은 업로드 대상에 포함하지 않는다.
- 스크린샷은 체험 모드 예시이며, 눈으로 확인한 화면에 자격증명이나 개인 Notion 주소는 없다. 이전 제품명을 담은 과거 검증 자료다.

## 실행 환경의 제한

현재 서버는 `0.0.0.0`에서 수신하며 로그인이나 사용자별 권한 검사가 없다. 서버에 접근 가능한 사용자는 연결된 Notion 데이터의 조회·추가 및 공유 연결 교체를 할 수 있다. 같은 출처 확인은 사용자 인증을 대신하지 않는다. HTTP를 사용하므로 LAN에서 입력한 토큰과 데이터의 전송 암호화도 제공하지 않는다. 신뢰할 수 있는 개인 네트워크에서만 사용하며 인터넷이나 공유 네트워크에 그대로 노출하지 않는다.

`Host`를 제한하지 않고 요청의 `Host`로 비교할 출처를 구성하므로 DNS rebinding 방어는 확인되지 않았다. 브라우저·DNS·네트워크의 실제 동작을 포함한 공격 재현은 수행하지 않았다. 서버 배포 전 허용 호스트 검증, 인증 및 HTTPS 구성이 필요하다. GitHub 비공개 저장소 설정은 실행 중인 앱의 접근 제어를 제공하지 않는다.

정적 파일은 지정 경로만 제공하고, Notion 호출은 고정 HTTPS 출처를 사용하며 리다이렉트를 거부한다. 브라우저의 동적 텍스트 이스케이프와 토큰 저장 처리도 검토 범위에 포함한다. 이 관찰은 모든 주입 공격의 부재를 보장하지 않는다.

## 확인된 렌더링 문제

`lib/notion.mjs`에서 파싱한 추출 기록의 스냅샷은 `public/app.js`의 `renderRecord()` → `stepsTable()`로 전달된다. `stepsTable()`은 `step.interval`을 HTML 이스케이프 없이 삽입하므로, Notion의 해당 스냅샷 속성을 편집할 수 있는 사람이 값을 조작하면 HTML이 화면에 삽입될 수 있다. 현재 CSP가 인라인 스크립트를 막고 있으며, 이 점검에서는 스크립트 실행이나 토큰 탈취를 재현하지 않았다.

다른 Notion 편집자를 신뢰하지 않는 공유 사용 전에는 단계 간격 이스케이프와 스냅샷 구조 검증을 적용해야 한다. 이번 업로드는 실행 서버의 공개 배포가 아닌 비공개 소스 저장이며, 이 렌더링 문제는 미수정 상태로 명시한다.

참고: [OWASP Host Header Injection](https://wstg.owasp.org/latest/4-Web_Application_Security_Testing/07-Injection/17-Host_Header_Injection/).

## 검증 기록과 미검증 범위

- 이름 변경 직후 실행한 `npm test`: 종료 코드 0, 29개 통과. 이 실행은 본 정적 보안 점검 이전의 기능 검증이다.
- 이번 보안 점검에서는 대상 코드를 실행하지 않았다. 외부 네트워크 차단·격리된 루프백·환경 초기화·읽기 전용 소스·자원 제한을 모두 제공하는 실행 환경이 없어 동적 보안 검증은 미수행이다.
- 실제 Notion API 호출이나 운영 데이터에 대한 공격 테스트는 수행하지 않았다.
- 업로드 직전 선택한 파일 목록, 새 커밋의 부모 이력 부재와 원격 저장소의 비공개 상태를 확인한다.
