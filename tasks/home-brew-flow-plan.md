# 홈 화면 및 추출 시작 플로우 구현 계획

## 목표

기본 화면을 홈으로 바꾸고, 기존 원두·레시피·기록 저장 구조를 재사용해 다음 흐름을 완성한다.

`홈 → 원두 선택 → 레시피 선택 → 추출 안내 → 기록 폼 → 저장된 기록 확인`

## 승인 범위 및 완료 조건

- 기본 URL, `/#/`, `/#/home`에서 홈을 표시한다. 상단 메뉴는 홈·원두·레시피·추출 기록을 제공한다.
- 홈에는 `오늘의 한 잔을 시작해 보세요.`와 `추출 시작`을 표시한다. 홈 진입은 원두·레시피·기록 전체 조회를 호출하지 않는다.
- 원두 선택은 화면별 `listBeans` 읽기, 검색 `searchOptions`, 기존 페이지 커서 기반 더 보기로 동작한다. 빈 목록은 원두 등록 위치와 추출 흐름 복귀 경로를 안내한다.
- 레시피 선택은 선택 원두를 `getBean`으로 확인하고 `listRecipeSummaries`로 해당 원두의 레시피를 보여준다. 검색과 페이지네이션을 지원한다. 잘못되었거나 누락된 원두는 선택 단계에서 안전한 오류 화면을 보인다.
- 추출 안내는 원두·레시피 부모와 관계를 `getBean` 및 `getRecipeDetail`로 다시 검증한다. 주요 조건, 누적 시간·물 붓기 표, 추출 가이드를 표시하며 타이머 자동 진행은 추가하지 않는다.
- `추출 완료`는 기존 `/records/new` 기록 폼으로 이동하며 원두·레시피와 오늘 날짜를 채운다. 별점·컵노트를 저장하면 기존 기록 목록/상세에서 확인할 수 있다.
- 선택값은 뒤로 이동과 새로고침 후에도 URL로 복원한다. 미등록 원두 안내에서 등록 화면으로 이동하고 추출 화면으로 돌아올 수 있다.
- 직접 URL·새로고침, 잘못된/누락된 parent·recipe, 비정상 관계를 검증한다. 검색과 페이지네이션 상태가 잘못된 데이터를 선택 가능하게 만들지 않는다.
- 기존 기록 폼의 검색, draft 보존, 연결 변경 보호, journal·lock·unknown 중복 제출 방지 동작을 그대로 유지한다.
- 문구·레이아웃은 기존 green/ivory 스타일과 반응형 규칙을 따른다. 변경은 홈/추출 흐름과 필요한 테스트에 한정한다.

## 구현 순서

1. 기존 뷰·화면 로딩 테스트에 홈·흐름·prefill 회귀 케이스를 추가하고 RED 결과를 증거로 기록한다.
2. 홈 기본 라우트와 네 메뉴, 홈 화면을 구현한다.
3. 원두·레시피 선택 라우트와 검색·페이지네이션, 등록 안내, 선택 보존을 구현한다.
4. 관계를 검증하는 추출 안내 화면과 기록 폼 자동입력을 구현한다.
5. RED에서 추가한 테스트를 GREEN으로 만들고 기존 draft/연결/journal/unknown 보호를 회귀 확인한다.
6. `npm test`, `npm run build:pages`, `npm run check:pages`를 실제 실행한다. 환경이 허용되면 fake Notion 데이터로 모바일·desktop 브라우저 흐름도 확인한다.
7. Critic에게 검토 가능한 변경과 증거를 인계한다. 이 Worker 범위에는 merge·push·게시가 포함되지 않는다.

## 증거 위치

`docs/evidence/home-brew-flow-20261027/`에 RED/GREEN 로그, 전체 검증 로그, 브라우저 확인 결과(실행할 수 있는 경우), 요약을 보관한다.
