# 항목 삭제 기능 계획

## 목표와 완료 조건

카드 우상단 휴지통에서 봉지·레시피·추출 기록을 확인 후 Notion 휴지통으로 이동한다. 기존 원두 삭제의 journal, 단일 쓰기 lock, 응답 유실 복구, 데이터 소속 검증, 미저장 초안 보존을 유지한다. 기록이 참조하는 봉지·레시피 삭제와 의존성을 확정할 수 없는 경우를 차단한다. 레시피 삭제는 부모만 보관 처리하고 단계는 원본 그대로 둔다. 기록 삭제 후 기록·평가 집계·선택 목록을 최신 조회로 갱신한다.

완료 조건은 동작별 RED 증거 후 관련 테스트와 전체 `npm test`, `npm run build:pages`, `npm run check:pages` 통과, 가능하면 fake Notion을 쓰는 로컬 브라우저 확인, 변경·검증 증거 기록이다. 실제 Notion 데이터는 건드리지 않는다. main merge·push·게시와 Critic 검토는 Orchestrator에 인계한다.

## 작업 순서

1. 저장소 상태와 기존 원두 삭제 보장, 관계 모델, 테스트 관례를 확인한다. 새 계획 파일은 기존 미완료 계획을 덮어쓰지 않는다.
2. 삭제 범위와 안전 조건을 SPEC.md/PLAN.md에 맞춘다.
3. Notion 소속·휴지통 응답, journal target 유효성·단일 전송·unknown 상태 복구의 신규 회귀 테스트를 먼저 작성하고 실패를 기록한다.
4. 명령 계층에서 최신 조회를 바탕으로 의존성을 확인한다. 기록 참조가 있으면 봉지·레시피 삭제를 안내와 함께 거절하고, 제외·불완전·모호 관계는 fail-closed 한다. 기록 자체 삭제는 대상만 보관한다.
5. UI 카드별 확인 버튼과 항목명 확인을 추가한다. 삭제 후 기존 재조회 경로로 평가 집계와 기록 입력 선택지를 갱신하고 미저장 폼은 유지한다.
6. 레시피 부모 삭제 시 단계 페이지를 쓰거나 보관 처리하지 않으며, 보관된 부모가 목록·복사·새 기록 선택지에 나타나지 않는지 검증한다.
7. 관련·전체 테스트 및 페이지 빌드 검사를 실행한다. 가능한 경우 격리된 fake Notion 브라우저 환경만 사용한다.
8. `docs/evidence/entity-delete-20261023/`에 RED/GREEN, 명령·종료 코드·테스트 수, 브라우저 확인과 미검증 범위를 기록한다. 이번 변경만 선별해 커밋할 수 있으나 통합·게시·Critic 업무는 맡지 않는다.

## 위험과 통제

- 응답 유실은 삭제 성공 여부가 미정인 상태로 보존하고 재전송하지 않는다. 원본 페이지를 새로 읽어 사람이 확인해야 해소한다.
- 참조 관계가 없거나 잘렸거나 관련 데이터 행이 제외된 경우 삭제하지 않는다.
- 레시피 단계는 외부 원본을 보존한다. 과거 기록 snapshot도 삭제하지 않는다.
- 새로 저장하지 않은 작성 폼과 draft는 삭제 완료 시 초기화하지 않는다.
